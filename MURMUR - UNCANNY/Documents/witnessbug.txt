Let's dig right into the code from `main.js` and look at the logic inside your **Dynamic Witness Death Event Hook** to see exactly why a Pillager or Witch might still occasionally mourn a dead Villager.

Here is the exact block of code from your `main.js` that handles the faction validation check:

```javascript
// Faction Check: Ensure witnesses only respond if their OWN kind dies
if (witness.typeId !== deadEntity.typeId) continue;

```

On paper, this line looks like it completely solves the problem. If a Villager (`minecraft:villager_v2`) dies, any witness whose `typeId` is *not* `minecraft:villager_v2` should be skipped instantly.

However, there is a hidden architectural edge-case with how **Illager Captains** and **Sub-variants** are registered in your database that breaks this logic.

---

## 🔍 The Root Causes

### 1. The `minecraft:pillager_captain` Override Loop

At the bottom of your `dialogue.js` database, you have this line:

```javascript
DIALOGUE["minecraft:pillager_captain"] = DIALOGUE["minecraft:pillager"];

```

Because of this, when a Pillager Captain dies, the first line of the death event hook runs a safety check:

```javascript
if (!deadEntity || !DIALOGUE[deadEntity.typeId]) return;

```

If a **Pillager Captain** (`minecraft:pillager_captain`) dies, it passes this check because it exists in your database.

However, when the script scans for nearby witnesses, it looks for entities sharing the *exact* same `typeId`:

```javascript
const witnesses = deadEntity.dimension.getEntities({
    location: deadEntity.location,
    maxDistance: 10,
    types: [deadEntity.typeId] // Looking strictly for "minecraft:pillager_captain"
});

```

* Normal Pillagers (`minecraft:pillager`) standing right next to him will be **ignored** because their ID doesn't exactly match `minecraft:pillager_captain`.


* Worse yet, if a regular Pillager dies, a nearby Pillager Captain will **ignore it** because their IDs don't match.



### 2. The Shared Faction Structural Blind Spot

While `witness.typeId !== deadEntity.typeId` stops cross-talk between Pillagers and Villagers, **it does not stop cross-talk between different sub-variants of Illagers or Piglins**.

* If a `minecraft:vindicator` dies, a nearby `minecraft:pillager` won't say a word, even though they are in the same raiding party!
* If a `minecraft:piglin_brute` dies, a normal `minecraft:piglin` completely ignores it.

### 3. Engine-Level Event Deserialization (The Ghost Glitch)

In rare high-lag situations or when an area is hit by area-of-effect damage (like splash potions, fire, or explosions), multiple entities die on the exact same tick.

When Minecraft flushes the `entityDie` event queue, if a witness entity is flagged as dying or dead on the *same tick* but hasn't been completely garbage-collected by the engine yet, `witness.isValid()` can occasionally return `true` for a split second right before the entity drops its inventory. If its data properties corrupt or read as empty strings during the death animation frames, `witness.typeId !== deadEntity.typeId` evaluates to `"" !== ""` (which is `true`!) or bypasses completely, causing a glitch where a dying witch "witnesses" a nearby villager death and speaks right before vanishing.

---

## 🛠️ The Fix

To completely eliminate the crossover bug, we need to transition the system from strict **ID matching** to **Faction Group matching**.

Replace the `world.afterEvents.entityDie.subscribe` block in your **`main.js`** file with this rock-solid, group-aware version:

```javascript
// --- DYNAMIC WITNESS DEATH EVENT HOOK (FIXED) ---
world.afterEvents.entityDie.subscribe((event) => {
    const deadEntity = event.deadEntity;
    if (!deadEntity || !DIALOGUE[deadEntity.typeId]) return;

    // 1. Group strict factions into structural arrays
    const FACTION_GROUPS = [
        ["minecraft:villager_v2"],
        ["minecraft:pillager", "minecraft:pillager_captain", "minecraft:vindicator", "minecraft:evoker"],
        ["minecraft:piglin", "minecraft:piglin_brute"],
        ["minecraft:witch"],
        ["minecraft:enderman"],
        ["minecraft:wither_skeleton"],
        ["minecraft:blaze"]
    ];

    // Find which faction group the dead entity belongs to
    const deadFaction = FACTION_GROUPS.find(group => group.includes(deadEntity.typeId));
    if (!deadFaction) return; // If no group maps, bail out safely

    const lostEntityName = deadEntity.nameTag || "our friend";

    // 2. Query for ANY entity belonging to that specific faction group
    const witnesses = deadEntity.dimension.getEntities({
        location: deadEntity.location,
        maxDistance: 10,
        types: deadFaction // Fetches ALL members of the faction group at once
    });

    if (!witnesses) return;

    for (const witness of witnesses) {
        // Strict live-engine validation checks
        if (!witness || !witness.isValid() || witness.id === deadEntity.id) continue;
        if (witness.typeId === "minecraft:piglin" && witness.hasTag("minecraft:zombified")) continue;

        // Double-check Engine-level health component sanity to prevent ghost corpse triggers
        try {
            const health = witness.getComponent("minecraft:health");
            if (health && health.currentValue <= 0) continue; 
        } catch(e) { continue; }

        // 3. Faction Group Check: Safeguards cross-talk (e.g. Pillager Captains mourn normal Pillagers, but never Villagers)
        if (!deadFaction.includes(witness.typeId)) continue;

        const playersNearWitness = witness.dimension.getEntities({
            location: witness.location,
            maxDistance: 8,
            types: ["minecraft:player"]
        });
        if (!playersNearWitness || playersNearWitness.length === 0) continue;

        // Access dialogue pools cleanly using the witness' mapping configuration
        const pool = DIALOGUE[witness.typeId];
        if (pool && pool.death && Math.random() < 0.75) {
            system.runTimeout(() => {
                // Final post-delay engine safety layer check
                if (witness && witness.isValid()) {
                    try {
                        const hCheck = witness.getComponent("minecraft:health");
                        if (hCheck && hCheck.currentValue <= 0) return;
                    } catch(e) { return; }

                    const finalPlayers = witness.dimension.getEntities({
                        location: witness.location,
                        maxDistance: 8,
                        types: ["minecraft:player"]
                    });
                    
                    if (finalPlayers && finalPlayers.length > 0) {
                        let deathMessage = getRandomElement(pool.death);
                        deathMessage = deathMessage.replace(/{dead_name}/g, lostEntityName);
                        sendCleanChat(witness, deathMessage, finalPlayers);
                    }
                }
            }, Math.floor(Math.random() * 15) + 10);
            break; // Loop broken successfully; single out-burst per death instance achieved
        }
    }
});

```

### What changed?

1. **`FACTION_GROUPS` Matrix**: Villagers are locked into their own array. Illagers, Vindicators, Evokers, and Captains are lumped together. Now, if a Pillager Captain dies, a normal Pillager can step up and accurately mourn him, but a Witch or Villager will remain completely silent.
2. **Sanity Health Checks**: Added a wrapped `minecraft:health` check inside the loop. This stops entities that are dying on the exact same tick from firing zombie/ghost dialogue packets before they disappear from the simulation entirely.
